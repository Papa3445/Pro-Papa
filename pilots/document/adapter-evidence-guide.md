# Using a Pro-Papa Adapter Result

## What the result actually establishes

A passing adapter report establishes only the bounded mechanical checks that the corresponding adapter performed. For software, these checks cover syntax rather than runtime behavior. For research, they cover source identifiers and structured citation references rather than the truth of those sources. For documents, they cover headings, prose length, and obvious placeholders.

## What still requires evidence

A reviewer should inspect the task's actual acceptance criteria and make an independent judgment about usefulness and correctness. Software needs genuine runtime tests; research needs a source audit; and documents need substantive content validation. A hash verifies which bytes were recorded but does not establish that the evidence is truthful.

## Recommended handoff

Attach the real artifact, its adapter report, domain-specific evidence, and a traceable review result. Document failures and changes, re-run the checks after correcting an artifact, and avoid marking the task complete before all required evidence is available. The separate-reviewer role in this sample is simulated for lifecycle testing and is not provider-authenticated.
