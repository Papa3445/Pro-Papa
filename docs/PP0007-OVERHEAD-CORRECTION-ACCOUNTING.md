## Accounting decision

Different execution modes have different clock boundaries, tools, environments, datasets and permissions. They are **not** measurements of the same thing. The owner's October 25 acceptance of practical day-to-day responsiveness is a legitimate product decision; it does **not** create a controlled effect size, matching token ledger, correction-time estimate or verified total duration. Do not undertake a fresh costly speed trial solely to restate this acceptance. [Roadmap/owner signoff](https://github.com/Papa3445/Pro-Papa/pull/32).

## Corrective interactions: a recorded zero does not mean zero actual human corrections

The archived seven-case Node JSON contains `correctionInteractionsObserved:0` for each fixed input, but also explicitly says `correctiveInteractionsMeasured:false` and `actualUserCorrections:"not_observed_in_single_pass_automated_fixtures"`. No interactive clarification path was run. Therefore the number of actual human corrections for either assistant arm is **`null`**, **not** 0. The structured host has `actualHumanCorrections:null` and `correctiveInteractionsMeasured:false`. The post hoc website report does not give a verified conversation-by-conversation count of retries, corrections or human rework minutes. Owner acceptance does not change that.

A later user-observable matched follow-up should separately time *human corrective turns* and assistant processing, label actual elapsed boundaries, and show the source artifact and matching permission set. This is optional prospective evaluation unless the original task acceptance needs to be formally completed or changed; prior results must never be backfilled.

## Unit and trace constraints

- **Measured**: sample host-call `elapsedMs` within Node; `providerCalls` and `transportCalls` instrumented by the host; one disposable-project durable tracking retry **10.926 ms** in the granted report; separate structured 4/4 calls **4.749 ms**. The durable probe's one temporary task is not a real production task.
- **Reported but not reproduced here**: UI *Worked for* values and anecdotal PDF/tool-run labels. These are seconds or rough seconds, not equal to the Node `elapsedMs` boundary.
- **Unknown**: comparable end-to-end clock time, true token counts, paid inference cost, model and grant parity, Netlify p50/p95, per-turn provider-side tool trace, correction count, human work minutes, quality-adjusted overhead and statistical superiority. **Use JSON `null`, not zero.**
- **Out of scope**: further JWKS/Netlify fixes already proposed in independently reviewed [PR #38](https://github.com/Papa3445/Pro-Papa/pull/38). Its local warm-instance test provides no measured production savings, and distributed concurrency is unproven.

The original seven-case trial fixture remains Git blob `aa07d8296ab8c4ad492ec02863bd4203bb90ead4`. The preregistered UI-v2 study has **0 of 42** future slots collected, not a regrading of the seven historical screenshots. Neither the post hoc 18/21 vs 21/21 score family nor the different 21/28 vs 23/28 secondary rubric gives a controlled efficiency ratio. No developer PR or provider CI can change this classification.
