# PP-0007 — reuse audit for existing ChatGPT baseline evidence

**Status:** historical evidence reconciliation only. **No new ChatGPT conversations, new grades, or benchmark completions are claimed.** Prepared against `main` commit `216d68e4395617ac9a9db7a6df9bb7062c7c9031` on 2026-10-25. The authoritative `.pro-papa/tasks.json` PP-0007 state remains `in_progress`; this audit does not revise its acceptance criteria or its review pin.

## Decision

**Do not reflexively rerun the existing regular-ChatGPT screenshots or start all 42 prospective UI-v2 conversations merely to validate the already demonstrated OAuth/MCP engineering integration.** Retain prior baseline material as *retrospective/descriptive evidence*, first recover and evaluate the originals privately, and distinguish two independent questions:

1. **Integration/security question:** Does the explicit deployed read-only MCP route execute permitted tasks, validate released results and deny the tested unauthorized access? Real ChatGPT math/text/research calls and the independently reviewed anonymous-denial probe materially answer this bounded question. They do **not** demonstrate an always-on Project response interceptor.
2. **Comparative user-outcome question:** Does the Pro-Papa Project or bounded Node host improve quality, correction count or cost versus direct ChatGPT across all seven user-task categories? Existing screenshots are useful leads but do **not** establish matched, independently graded, provider-authenticated prospective comparisons or superiority. The predeclared 42-slot UI-v2 protocol addresses a *separate* regular-ChatGPT-versus-Pro-Papa2-Project comparison, not the original Node-host experiment.

No post-hoc rerating or conversion of historical observations into UI-v2 slots is permitted. A shorter, separately preregistered *exploratory* follow-up may be proposed if the owner prioritizes a practical go/no-go decision, but it must not masquerade as execution of UI-v2 or silently change PP-0007's acceptance criteria.

### Reuse classification

- **Reuse now, with correct attribution:** immutable case identities, existing **native/structured host results**, CI proofs, approved scoped production MCP integration/security observations, and the **reported retrospective comparison** as historical descriptive context.
- **Conditionally reuse after private verification:** seven regular-ChatGPT screenshot sets, original actual submitted prompts, any full response transcripts or original code ZIPs, dated provider logs, original correction/elapsed time measurements, and old Pro-Papa2 answers. A verified retrospective record remains *retrospective* even after private readback.
- **Do not claim or backfill:** individual prospective ratings, matched-token overhead, comparability of different permissions, provider-authenticated provenance for operator screenshots, missing software artifacts, missing grader rationales, and any of 42 UI-v2 slots. Preserve unknown as `null`.

## Acceptance-gap assessment

Original PP-0007 acceptance in `.pro-papa/tasks.json` requires seven-category representative requests, actual execution/evidence and negative controls, output-quality/task-success comparison with a direct-assistant baseline (including corrections and measurable overhead), and final exact-head CI plus genuine independent milestone review. Existing repository tests provide substantial **reference-host execution, synthetic/supplemental safety, persistence and real OAuth/MCP deployment** evidence. **Unresolved comparison blockers** are: independently recoverable full baseline/project artifacts, common permission/model context, objective quality judgments for memo/planning/software/novel, comparable timing/correction counts, missing token usage explicitly marked unknown, and final outcome-level independent review. Merely recovering screenshot files does not fix all of those.

The frozen UI-v2 **42-conversation** study is a separately preregistered *stronger observational performance comparison*. Its execution is **not expressly the same thing as** the seven original Node-host pilot acceptance; no source authorizes presenting an unrun UI-v2 study as completed. Conversely, approving an integration PR does not complete the original seven-category quality comparison. The original task is **not ready for closure**.

## Least-duplicative next actions (gates, not fabricated results)

1. **Private originals audit, before any re-runs:** locate the seven regular screenshot sets and retrospective project-arm records outside this public repository; verify case identity, actual exact sent prompts, complete outputs, date, source/ChatGPT configuration and any code ZIPs. Keep missing items explicitly missing and do not publish user text/screenshots.
2. **Evidence matrix and independent quality review:** for each case, record original source existence separately from independent inspection, and independently score only recovered outputs under a labeled **retrospective** rubric (never apply the prospectively frozen UI-v2 grades post hoc). Check runnable code symmetrically or leave software correctness unverified. Leave unknown model/timing/tokens/corrections as `null`.
3. **Choose the goal before more trials:** if the priority is *production integration feasibility*, the positive/negative MCP evidence already supports a bounded engineering decision and no 42-conversation rerun is needed for **that claim**. If the priority is a general **ChatGPT improvement** claim, collect valid new matched observations with parity and independent graders; the already-frozen UI-v2 protocol remains 42 fresh conversations. A **new smaller exploratory study**, if deliberately selected, needs its own preregistration, separate grades and explicitly lower strength of inference, not a replacement for UI-v2.
4. **Only fill unavoidable gaps:** where recovered history is inadequate for a specific original case, use the existing immutable original seven-case prompts and a separate, independently reviewed collection protocol with declared permissions. Do not opportunistically choose results after seeing answers, combine Node host and ChatGPT Project as the same arm, or assert superiority from a tiny uncontrolled sample.
5. **Final gate:** publish only non-sensitive aggregate and source hashes, run exact-head CI, obtain new authenticated independent **outcome-level** review and update task ledger through a scoped reviewed PR only if original acceptance genuinely holds or a separately approved scope change exists.

**Present verdict:** Existing regular-ChatGPT evidence is *not zero*. It should not be thrown away. However, the public, reviewable evidence is insufficient to turn the historical observations into verified matched quality/overhead results or to mark either the original paired-quality acceptance or any UI-v2 prospective slot complete.
