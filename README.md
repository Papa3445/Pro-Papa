# Pro-Papa

**A general-purpose, repository-backed operating framework for AI-directed work.**

Pro-Papa extracts the reusable ideas behind [Ironshade Vector](https://github.com/papa4568/ironshade-vector): persistent ordered tasks, scoped execution, domain-specific acceptance, evidence integrity, failure recovery and independent review. It deliberately does **not** copy game logic, graphics tests, Android pipelines, or expensive experimental CI governance.

## PP-0001: permission-scoped domain checks

The built-in software, research and document adapters provide **real, bounded, read-only checks** instead of only accepting self-reported proof. An active task selects its adapter by profile; `.pro-papa/adapter-policy.json` can revoke permission but cannot supply executable commands. Check an active task with `node bin/pro-papa.mjs adapter-check --id PP-0001 --actor IMPLEMENTER --file src/adapters.mjs`. The adapter writes a SHA-256-backed report and records pass/fail proof; failing checks exit nonzero. See [the detailed adapter contract](docs/ADAPTERS.md). Syntax, citations and structure checks are **not** quality, truth or security certifications.

## What's working in v0.1

- Deterministic task selection and resume: ordered queue, one active task, validated dependencies, blocked-state handling and cycle detection.
- Domain profiles: general, software, research, document, data, operations. All require an artifact, validation and a distinct reviewer declaration; domain-specific proofs add tests, citations/sources, or calculation checks.
- Evidence recording: every evidence declaration is linked to a project-local real file and SHA-256 digest; modified files invalidate closure.
- CLI-backed task lifecycle: initialize, add, select, start, hand off, record proof, block/unblock and close.
- Portable bootstrap: initialize a separate project without copying the game repo.
- Dependency-free Node.js CLI (Node 20+), automated tests and GitHub Actions CI.

**Important boundary:** The CLI verifies bookkeeping, file existence and hashes. It cannot establish that an AI's evidence claims are truthful, that a review actor is authenticated, or that work actually happened. It does not run an AI model or continue working after a ChatGPT turn ends. Authorized tools/agent runners and genuine independent inspections supply those abilities. See `docs/SECURITY.md`.

## Quick start

```bash
npm test
node bin/pro-papa.mjs validate
node bin/pro-papa.mjs next
node bin/pro-papa.mjs handoff --id PP-0001
```

Start a fresh independent project:

```bash
node /path/to/Pro-Papa/bin/pro-papa.mjs init --root /path/to/new-project --name "My project" --guide true
node /path/to/Pro-Papa/bin/pro-papa.mjs add --root /path/to/new-project \
  --title "Research alternatives" --objective "Compare three options" \
  --profile research --accept "Source-backed comparison with a recommendation"
node /path/to/Pro-Papa/bin/pro-papa.mjs next --root /path/to/new-project
```

A project can use a shared installation of Pro-Papa's CLI while retaining its own `.pro-papa/` state and profile configuration. The `AGENTS.md` generated by `--guide true` is intentionally short; the agent runner still needs a connected model/tool environment.

## Completing a task

```bash
node bin/pro-papa.mjs start --id PP-0001 --actor implementer
# Perform real work and generate actual project-local artifact and proof files.
node bin/pro-papa.mjs proof --id PP-0001 --kind artifact --file outputs/result.md --actor implementer --note "Final output"
node bin/pro-papa.mjs proof --id PP-0001 --kind test --file evidence/tests.txt --actor implementer --note "Observed tests"
node bin/pro-papa.mjs proof --id PP-0001 --kind validation --file evidence/validation.md --actor implementer --note "Acceptance evaluation"
node bin/pro-papa.mjs proof --id PP-0001 --kind review --file evidence/review.md --actor separate-reviewer --note "Reviewed exact output"
node bin/pro-papa.mjs close --id PP-0001
```

The `proof` command does not execute the tests mentioned in your report. The agent must actually run them and save authentic evidence. A different actor name alone does not prove independent identity.

## Structure

| Path | Purpose |
|---|---|
| `AGENTS.md` | Portable AI operating instructions |
| `.pro-papa/tasks.json` | Authoritative project task queue and recorded proofs |
| `.pro-papa/profiles.json` | Domain-specific evidence requirements |
| `src/core.mjs` | State transitions, validation and SHA-256 evidence rules |
| `bin/pro-papa.mjs` | CLI boundary used by agent or human |
| `tests/` | Automated positive and adversarial checks |
| `prompts/` | Implementer and read-only verifier roles |
| `docs/` | Architecture, migration, security and version roadmap |

## Current status

**Version 0.1: working task-control and evidence-integrity foundation.** It is not yet a complete autonomous agent platform. The ordered next milestones in `.pro-papa/tasks.json` add typed domain adapters, authenticated independent review and cross-domain pilot validation. No task is marked complete unless backed by actual checks and review.
